# aether-vc1

Pure Rust decoder for SMPTE 421M (VC-1) **Advanced Profile** video, written for a browser-only
player: Chrome has no VC-1 decoder, so this crate runs as WebAssembly inside Web Workers.
No C, no FFI, no threads inside the crate, no `unsafe` except one range-checked kernel
(the deblocking filter) and the C-ABI exports in `src/abi.rs`.

It is a port of the FFmpeg `libavcodec` VC-1 decoder (see `NOTICE`; LGPL-2.1-or-later) and produces
**bit-identical** output to it.

## What it decodes

* Advanced Profile (`WVC1`, Annex G start codes: sequence header, entry point, frame, field, slice).
* Progressive, interlaced **field** and interlaced **frame** pictures; I, P, B and BI.
* 1MV / 4MV / mixed-MV, quarter-pel bicubic and half-pel bilinear MC, chroma 1/8-pel MC.
* B direct / forward / backward / interpolated modes, fractional (BFRACTION) MV scaling.
* Intensity compensation, overlap smoothing, in-loop deblocking, DQUANT profiles, VSTRANSFORM
  (variable size transforms), skipped pictures, slices, multiple entry points / size changes.
* RANGE_MAPY / RANGE_MAPUV (applied to output frames only; FFmpeg ignores them, set
  `Decoder::apply_range_map = false` for FFmpeg-identical output on such streams).
* Output: planar 8-bit 4:2:0 in display order, `pts` passed through, interlace / TFF / RFF / RPTFRM
  metadata (pull-down is exposed, not applied), bounded reference set and output queue.

Not implemented: Simple and Main profile (`WMV3`), PsF, pan-scan windows, 4:2:2 / 4:4:4, HW
accelerator side data, sprite/image modes.  The sequence header of those profiles returns
`Error::Unsupported`.

## API

```rust
let mut dec = aether_vc1::Decoder::new();
dec.set_extradata(codec_private)?;            // Matroska CodecPrivate (optional for Annex G streams)
dec.decode(packet, pts)?;                     // one access unit (container packet or Annex G unit run)
while let Some(frame) = dec.take_frame() {    // display order
    let (y, stride_y) = frame.plane(0);       // also 1 = U, 2 = V
    // frame.width, frame.height, frame.pts, frame.interlaced, frame.top_field_first,
    // frame.repeat_first_field, frame.repeat_pict, frame.pict_type ...
}
dec.flush();                                  // end of stream: emits the delayed reference picture
```

Raw Annex G byte streams can be fed with `Decoder::decode_annexg` or split with
`decoder::split_access_units`.  Malformed data never panics: macroblock errors are counted in
`Decoder::errors` and the picture is still output.  Pictures larger than 4096x2304 are rejected.

`src/abi.rs` exports a raw C ABI (`vc1_create`, `vc1_decode`, `vc1_next_frame`, `vc1_frame_plane`,
...) for the `wasm32-unknown-unknown` cdylib; `tests/wasm/run.mjs` is a Node harness for it.

## Build, test, bench

```
cargo build --release
tools/regen-fixtures.sh            # extract fixtures from the read-only test media (git-ignored)
cargo test --release               # conformance (needs fixtures), golden vectors, robustness
cargo test --release -- --ignored  # full-file comparison against FFmpeg
tools/difftest.sh 1 200 98 90 8 1 8000 1   # differential fuzz against ffmpeg (see script header)
tools/build-wasm.sh [simd]         # wasm32 build (simd = +simd128)
tools/bench.sh                     # native + Node/WASM speed with MD5 check
```

`src/tables.rs` is generated by `tools/gen_tables.py` from the FFmpeg sources.

## Verification

* Both real 1080p23.976 Advanced Profile streams (`VC1-1080p23.976-LPCM7.1.mkv`: 1432 frames,
  `DTS-HRA5.1_VC1-23.976.mkv`: 1077 frames) decode bit-exactly against `ffmpeg -f framemd5`.
* Because those files are progressive and use neither overlap, intensity compensation nor
  interlaced coding, `testgen` builds streams with valid headers and *random* macroblock payload
  (repaired with this decoder until it parses without error).  Thousands of such streams
  (progressive, interlaced frame, interlaced field, slices, skipped pictures, 64 to 260 px wide; narrower pictures are skipped because FFmpeg itself corrupts its chroma edge buffer when the chroma stride is 16 bytes or less)
  decode identically to FFmpeg run with `-cpuflags 0` (scalar C DSP).
